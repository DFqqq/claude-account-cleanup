# Claude 旧账号清理

让员工用一句话完成旧账号处理，由 Codex 定位、执行和核验。现有新账号优先保护。版本 1.2.1。

验证范围：Windows 原生虚构测试通过；macOS 文件、ACL 与扩展属性已在 GitHub Runner 的虚构数据中验证。真实 Keychain 授权及浏览器、桌面 UI 仍需实机验证，逐入口核验。

建议调用：`使用 $claude-account-cleanup 完整清理旧 Claude 登录并重置旧标识；尚未登录新号，保留项目、会话、MCP 授权和公司网络配置。`

## 安装与反馈

仅安装请求只检查包和运行时，不查看真实账号。解压到临时工作目录后，优先使用包内 `scripts/install_skill.py --dest-root 实际用户技能目录` 完成安装及逐文件核验；按文件摘要一致才返回已安装；版本号相同但内容不同也不能跳过。用户已要求安装最新版或更新时使用 `--upgrade`，原 Skill 保存为同一技能根下的隐藏备份；仅安装且未授权覆盖时保留原版本。此过程不接触 Claude 数据。

自动查找已有可用 Python（`python`、`python3` 或 Windows `py -3`），核对 3.10+ 后固定其绝对路径。读取中文文件明确使用 UTF-8，Python 命令使用 `-B -X utf8`。无可用解释器时一次说明缺少的依赖，不让员工反复试命令；不静默安装软件。

员工反馈保持简短：安装完成、检查完成、清理完成及需要本人处理的事项。路径、字段、哈希和自动修复的工具错误写入本地记录，不逐项展开。正常清理不追问邮箱、资料夹、删除字段或是否继续；不要在反馈后提前结束，继续完成已授权流程。

任务被中断后收到“继续”，先读取本地回执并核对现状，只执行剩余项，不要求员工重新提供已知信息。没有回执不代表未修改：核对目标状态后再决定是否需要新计划，不直接重放原清理命令。

保存草稿、正常退出旧客户端、选择不重名的回执文件、纠正命令语法或编码问题由 Agent 自行处理。仅在无法保存/正常退出、系统权限必须本人授权、缺少必要依赖时集中说明需要的动作。发现新账号或缺少某个入口控制能力时保护该入口、完成其他明确部分，不能反复询问后扩大权限或清理范围。

## 执行边界

- 用户已经要求清理且说明旧号/保留范围时，直接完成必要准备和已授权操作，不反复询问邮箱、文件位置或清单。授权不明确或发现不同账号时，只保护对应项；可继续独立、明确的部分。
- 制作 skill、研究教程、只读检查、模拟或测试请求不授权清理。虚构测试只能访问测试目录，不读取真实 Claude、浏览器、钥匙串或登录环境。
- 默认保留所有项目和未提交改动、会话及 memory、输入历史、file-history、规则、技能、插件、hooks、MCP 配置及授权、网关密钥。保留公司 VPN、代理、路由、DNS、系统环境变量和公司策略。
- 不整删目录/配置/凭据容器，不清空全部浏览器数据，不强退进程，不卸载/安装客户端，不自动登录新号，不发模型消息。项目和历史正文不用于生成在线报告。
- 本技能处理本地登录状态，不判断封禁原因，不将标识重置表述成解除服务端关联。遥测、时区、密钥轮换和网络设置均独立于本次清理。

## 1. 定位实际入口

读 [平台与入口处理](references/platforms.md)，按实际存在的浏览器、Claude 桌面版、CLI、VS Code 分别定位。核对实际配置目录、`CLAUDE_CONFIG_DIR`、共用凭据来源及当前版本；不凭一个默认路径推断全部入口。

缓存账号信息仅是线索。发现正常新账号、不同账号混用或归属无法区分时，排除对应资料夹、凭据命名空间和所有共用入口。用户不需要提供密码、验证码或令牌。只能确认部分旧状态时，只处理明确部分。

完整清理包含用户已要求的旧随机客户端标识重置；按 [旧标识重置](references/identifiers.md) 自动确定已核实字段并加入计划，不因其不是 OAuth 凭据就漏掉。仅退出登录不额外重置标识。以本机版本和字段用途为依据，不把固定字段名单当成必删项。允许的旧本地标识不存在就记录不存在，不创造 `deviceId`，不改系统硬件标识。CLI 与 VS Code 共用文件只处理一次；桌面版、浏览器独立核验。

## 2. 保存工作并制定精确计划

保存工作后正常退出目标 Claude 会话，使其不再写入；不关闭无关 IDE，不使用强制结束。不要在被清理的 Claude Code 活跃会话中修改自身状态；改用外部 Codex 环境执行。运行中的新账号不得为清理旧号而关闭。

脚本只接受显式路径，不自行扫描主目录。按 [脚本用法](references/operations.md) 生成 `spec.json` 和计划。明确列出需要修改的字段、真实配置目录与保留范围，将现有会话、工作配置、插件及共用文件纳入前后比较。计划和报告放在源目录外的本地工作目录。

优先使用经当前版本核实且不会清掉保留授权的官方退出入口；退出也会改状态，可能撤销凭据，不能作为只读探测。官方退出完成后重新生成计划，不能沿用退出前指纹。

## 3. 精确清理

- JSON：使用 `cleanup_guard.py plan`、`apply`。只移除确认属于旧号的字段；Windows/Linux 文件凭据只处理 `claudeAiOauth`，保留 `mcpOAuth` 等其他字段。
- macOS：确认准确 Keychain 路径、service 和 account 后使用 `keychain_guard.py`；秘密只在本机内存处理，禁止通过命令行 `-w` 写入完整凭据、输出原始内容或整项删除混存条目。系统授权提示由用户在系统界面处理，不索取钥匙串密码。
- 浏览器：按 [浏览器处理](references/browser.md) 自动选择原资料夹的界面控制或配套 `browser_cleanup.mjs`；协议工具处理选中站点 Cookie、网站存储和已保存草稿的目标标签页，并核验保护范围。缺少连接时先检查已有浏览器/桌面控制能力；确需本人授权时集中请求一次，不把手动改数据库交给员工。
- 桌面版：使用现有控制工具按平台说明退出；不直接修改 Cookie/SQLite/LevelDB 数据库。任何入口都不能用整删资料夹或新建资料夹冒充清理。
- 旧备份、调试日志、遥测队列：只读定位并判断归属，不按日期或名称批量删除。文件工具仅支持对白名单格式旧配置备份中的精确字段做处理；额外文件清理不是默认动作。

不生成原始令牌或完整凭据备份。文件变更使用受限临时文件和原子替换，保留权限；脚本无跨文件事务，失败可能留下部分完成状态。记录已完成项，重新检查后再处理余项，不自动恢复整个旧账号配置或覆盖后来登录的新账号。

## 4. 核验与交付

逐入口确认旧登录状态的处理结果；单凭 `auth status`、退出页面、ID 变化或脚本返回成功，都不能替代其他入口的核验。不要为检验而发送模型请求。

文件修改后核对：选中旧字段已移除，未选 JSON 字段语义一致；项目、会话、MCP 与工作文件内容和权限一致。Keychain 另核对保留子项。浏览器核对原资料夹的目标站点数据；工具只能证明部分内容时准确限定结论。

若本机客户端在正常后续启动时生成新标识，可比较本地指纹；不为了满足“ID 必须变化”启动或登录账号。已移除与已重新生成分别记录。

同事只需看到：**已完成 / 保留核验 / 未完成原因**，以及本地记录位置。技术细节留在本地回执中。把“未安装”“未找到”“权限不足”“不同账号已保护”分开，不能把未完成写成全部清理成功。

## 维护与验证

修改相关逻辑后运行 `python -B -X utf8 tests/test_cleanup.py`、`python -B -X utf8 tests/test_install.py` 、`python -B -X utf8 tests/test_identifiers.py` 和 skill 结构校验；仓库完整隔离测试使用 `run_validation.py`，浏览器协议测试见 `references/browser.md`。所有测试仅使用自动创建的虚构目录。Windows 原生文件替换与 ACL 在 Windows 测；macOS 文件与 ACL 在 macOS 测，真实钥匙串原生调用仍需 Mac 实机专项验证。

设计参考：[cc-clean](https://github.com/luwill/cc-clean) 的精确范围、共用凭据保护和验证思路；此处脚本为独立实现。认证位置以 [官方文档](https://code.claude.com/docs/en/authentication) 和本机版本为准。
